# Writing Rules

Use for articles, websites, product docs, technical docs, and user-facing docs.

## Human-Like

- Do not use em dashes.
- Cut AI puffery and filler: no "pivotal/crucial/seamless/robust/groundbreaking", no "delve/leverage/foster/realm/tapestry", no empty "-ing" tails ("ensuring reliability", "showcasing features").
- Avoid formatting overuse. No emoji decoration or bold on every other word.

## Strong prose

- Prefer active voice and positive form.
- Use definite, concrete, specific language.
- Omit needless words. Put the emphatic word at the end of the sentence.
- Keep related words together. Keep to one tense in summaries.

## Simple

Keep docs small. Merge content into existing sections instead of creating new ones.

Simplicity increases by audience: technical docs (simple), product docs (simpler), user-facing docs (simplest). Use plain English a junior can follow without prior knowledge. Avoid jargon.

- Technical docs: high level. Code is the source of truth; link to code instead of repeating it.
- Product docs: for non-tech readers. Minimal, clear tech terms only when they aid understanding.
- User-facing docs: for customers. No tech language. Speak to features, value, and how-to. Hide internals.

## Code comments

- Comment the why (business logic, non-obvious behavior), not the what.
- If a name needs a comment to explain it, rename it instead.
